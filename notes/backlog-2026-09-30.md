## UX brainstorm (2026-09-30), grounded in a read of the code

Items marked **[bug]** were checked against the code, not just reported. Paths are
under `frontend/`.

### Fix first: broken or embarrassing, each small

- **[bug] Settings page cannot open.** No `#settings-page` div in `index.html`, so
  `router.js` returns early; bank details and invoice letterhead are uneditable.
- **[bug] Real parents and teachers see the role switch.** `#dock-role-btn`
  (`index.html:455`) is not hidden by `Dev.init` (`main.js:759`); nor are the
  "Viewing as" / "Teacher:" pickers. Server still enforces access, but a parent
  can flip into an empty admin UI.
- **[bug] A full class vanishes from the parent's own schedule**
  (`calendar.js:91` hides full classes after already filtering to their child's).
- **[bug] A parent with one child enrolled cannot request enrolment for a second**
  (the form only renders when they have no children, `dashboard.js:385`).
- **[bug] Teacher "Log Feedback" goes to a page that does not exist**
  (`dashboard.js:1184`).
- Admin setup checklist never renders (lives inside the parent dashboard).
- Dashboard links lose context: "payments awaiting verification" opens the Unpaid
  tab, not Awaiting Confirmation; "Mark" opens attendance with nothing selected.
- Reject / Mark Unpaid: no confirm and no reason sent to the parent.

### Admin (Nadine)

- **"Today" screen**: today's classes with attendance done/not done, payments
  to verify, overdue families, one tap into each.
- **Send by WhatsApp**: a button on an invoice or family bill that opens WhatsApp
  with the amount, due date and pay link filled in. Parents live on WhatsApp and
  email is allowlist-blocked, so this reaches them today.
- **Class modal that does things**: add student, take attendance, cancel this
  session (with a reason), reschedule, Close. Today cancelling a class is only
  possible by marking the teacher absent, which also writes payroll.
- **Search everywhere**: one box for student / parent / invoice / phone.
- Edit a draft from Run the month and land back on the review list.
- Enrol from a future date (the "Starting from" field is capped at today).
- One bulk check-in for admin and teacher, with a spinner and error count.

### Teachers

- **"My hours this month"** read-only card (payroll is admin-only today).
- **Undo own same-day attendance**, and confirm before "Absent + replacement"
  grants credits; show the 3-hour rule on screen, not only in a hover tooltip.
- **Progress report checklist**: who still needs a report this term, teacher
  pre-filled, the form usable on a phone.
- Decide Quick Note vs progress reports; parents see both today.
- Hide stat cards that link to pages teachers cannot open.

### Parents

- **Family bill** (built, waiting for deploy).
- **Show the QR / bank details with the exact amount inside the pay popup**, so
  paying and claiming happen in one place; hide "Pay Online" while no gateway is
  configured (it answers with an error today).
- **Report an absence** from the child card, which also records the "told us 3
  hours before" rule credits depend on.
- **Add to Google Calendar**: the iCal feed exists, nothing links to it.
- **Phone layout**: schedule as a day list instead of 7 cramped columns; child
  cards at 420px minimum overflow phones; tile taps also open the student popup.
- Progress report readable in the app, not only as a PDF download.

### Everyone

- **Phone pass**: modal widths fixed at 380-520px, inline-style grids the mobile
  CSS cannot override, and a dock that sits at 35% opacity until hover, which
  never happens on a touchscreen.
- **Accessibility**: the modal overlay is `aria-hidden="true"` with the dialog
  inside it, so screen readers skip every popup; no `aria-label` on icon buttons;
  clickable cards not reachable by keyboard; status shown by colour alone.
- Replace the remaining `confirm()` / `prompt()` with the app's own dialogs.
- One set of words: Mark / Attend / Attendance; Awaiting Confirmation /
  Pending Verification; Announcements / News.
